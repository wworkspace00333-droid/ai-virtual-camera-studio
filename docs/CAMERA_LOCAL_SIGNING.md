# Можно ли поставить свою камеру без платного аккаунта Apple — отчёт

Дата: 2026-11-12. Проверено на Mac mini M2 Pro (Mac14,12), macOS 27.2.1 (26B131) — та же версия macOS, что на целевом
M5. Никакие настройки безопасности не менялись; расширение не установлено (`systemextensionsctl list` — только OBS).

## Коротко

**Без снижения защиты macOS — нельзя.** Это доказано опытом, а не предположено (ниже). Единственный путь без
платного аккаунта — выключить SIP **и** проверку подписей ядра (AMFI) через Recovery, что снимает защиту со всего
Mac. Для цели «проверить приложение на своём M5» это не нужно: обработанное видео уже выходит в стороннюю
программу через установленную и подписанную камеру OBS Virtual Camera — тем же механизмом приёмника (sink),
что использует наше расширение.

## По этапам (повторно проверено 2026-11-12)

| Этап | Результат | Доказательство |
|---|---|---|
| 1. Компиляция | ✅ | `xcodebuild ... CODE_SIGNING_ALLOWED=NO build` → BUILD SUCCEEDED, без предупреждений; расширение встроено в `Contents/Library/SystemExtensions`, тип `SYSX`, arm64, ключ `CMIOExtension` на месте |
| 2a. Подпись ad-hoc | подпись валидна, **но непригодна** | хост с правом `com.apple.developer.system-extension.install` убит при запуске (SIGKILL, код 137); тот же двоичный файл без права — работает (self-check 11/12) |
| 2b. Подпись бесплатным сертификатом Apple Development (Personal Team) | подпись валидна, **но непригодна** | `codesign` с сертификатом команды-«Personal Team» — TeamIdentifier задан, профиля нет → тоже убит при запуске (код 137) |
| 2c. Профиль обеспечения для бесплатной команды | ❌ Apple не выдаёт | `xcodebuild -allowProvisioningUpdates` → «Personal development teams … do not support the System Extension capability» |
| 3. Активация | ❌ | хост, который может стартовать (без права), на `--activate-camera`: `OSSystemExtensionErrorDomain 2: Missing entitlement com.apple.developer.system-extension.install` |
| 4. Камера доступна программам | ❌ | не достигается без этапа 3 |

**Точный блокер:** активировать системное расширение может только приложение с правом
`com.apple.developer.system-extension.install`; ядро (AMFI) запускает такое приложение только вместе с профилем
обеспечения от Apple, где это право указано; Apple выдаёт такой профиль только командам платной программы
Apple Developer Program. Тип сертификата не помогает (2a и 2b дают одинаковый результат), бесплатная команда
профиль получить не может (2c), без права нет активации (3).

## Самый дешёвый законный путь

| Вариант | Цена для вас | Что нужно |
|---|---|---|
| **Войти в чужую платную команду** | 0 | владелец платного аккаунта добавляет ваш Apple ID на developer.apple.com → Users and Access (надёжнее с ролью Admin или App Manager: нужно зарегистрировать этот Mac и включить System Extension для App ID `com.aivcstudio.app`; если у роли не хватит прав, это делает владелец — не проверено, зависит от настроек команды); в Xcode входите этим Apple ID; `VCS_TEAM_ID` = ID той команды |
| **Apple Developer Program (частное лицо)** | 99 $ в год (или местная цена) | оформить, войти в Xcode, прислать Team ID |
| Освобождение от взноса | 0 | только для некоммерческих, учебных и государственных организаций в отдельных странах; частным лицам не предоставляется |

После любого из них: `VCS_TEAM_ID=<ID> scripts/build_camera.sh` (Xcode сам выпустит сертификат Apple Development,
зарегистрирует этот Mac и создаст профиль) → приложение в `/Applications` → одобрение в «Системные настройки →
Основные → Объекты входа и расширения → Расширения камеры» → проверка в QuickTime/FaceTime/Zoom. Developer ID и
нотаризация для этого не нужны — они нужны только для раздачи на другие Mac.

## Опыты

1. **Сборка Xcode с локальной подписью** (`CODE_SIGN_IDENTITY=-`, без команды):
   `error: "AIVirtualCameraStudio" requires a provisioning profile`. Xcode отказывается подписывать приложение с
   правом `com.apple.developer.system-extension.install` без профиля обеспечения Apple.
2. **Обход Xcode**: сборка без подписи (`CODE_SIGNING_ALLOWED=NO` → BUILD SUCCEEDED), затем ручная ad-hoc подпись
   `codesign -s - --options runtime --entitlements ...` хоста и расширения. `codesign --verify --deep --strict` — OK.
3. **Запуск хоста** с безобидной командой `--self-check` (расширение не активируется):

   | Подпись хоста | Результат |
   |---|---|
   | ad-hoc **без** права `system-extension.install` | запускается, self-check 11/12 |
   | ad-hoc **с** правом `system-extension.install` | процесс убит при запуске: SIGKILL, код 137 |

   Двоичный файл тот же; разница только в праве. Это право ограниченное (restricted entitlement): ядро (AMFI)
   разрешает его только вместе с профилем обеспечения, подписанным Apple. Самоподписанный сертификат из «Связки
   ключей» в этом отношении равен ad-hoc — Apple его не выпускала.

## Почему нет обходного пути при включённой защите

| Вариант | Почему не подходит |
|---|---|
| Самоподписанный сертификат | ограниченные права требуют профиль от Apple (опыт 3) |
| Бесплатный Apple ID (Personal Team) в Xcode | **проверено 2026-11-12**: `VCS_TEAM_ID=<personal team> scripts/build_camera.sh --no-install` → `error: Cannot create a Mac App Development provisioning profile for "com.aivcstudio.app". Personal development teams, including "…", do not support the System Extension capability.` Apple не выпускает бесплатным командам профиль с этим правом |
| `systemextensionsctl developer on` | при включённом SIP не работает (см. таблицу состояния); и даже включённый режим разработчика лишь разрешает расширения вне `/Applications` — проверку подписи и прав он не отменяет |
| Активировать расширение без нашего хоста | у `systemextensionsctl` нет команды установки; активирует только приложение с этим правом через `OSSystemExtensionRequest` |
| Старый DAL-плагин вместо расширения | DAL устарел и на современных macOS сторонними программами не загружается; это была бы переделка камеры, а не установка |

## Путь со снижением защиты (не выполнялся, только описание)

Нужно **всё** из списка, через Recovery (зажать кнопку питания → Параметры), с паролем администратора:

1. «Утилита безопасности загрузки» → **Сниженная безопасность** (Reduced/Permissive Security).
2. Терминал: `csrutil disable` (выключить SIP).
3. После перезагрузки: `sudo nvram boot-args="amfi_get_out_of_my_way=1"` (выключить проверку подписей ядром).
4. `systemextensionsctl developer on`.
5. Перезагрузка; затем установка нашим скриптом и одобрение в «Расширения камеры».

**Последствия, пока это включено:**

- SIP выключен: программы с правами администратора могут менять системные файлы и встраиваться в системные процессы.
- AMFI выключен: macOS запускает любой код с любой подписью или без неё и с любыми правами — защита от
  подменённых и вредоносных программ на уровне подписей перестаёт работать **для всех программ**, не только нашей.
- Сниженная безопасность загрузки: можно загружать неподписанные ядра и расширения.
- Часть функций может перестать работать: приложения iPhone/iPad на Mac, Apple Pay, воспроизведение защищённого
  видео (FairPlay) в Safari/Apple TV, некоторые корпоративные политики (MDM) сочтут Mac небезопасным.
- Обновления macOS могут вернуть часть настроек или требовать повторных шагов.

Возврат: Recovery → `csrutil enable`, `nvram -d boot-args`, «Полная безопасность». Это обратимо, но на всё время
опыта Mac защищён заметно хуже. **Я не рекомендую этот путь** ради камеры, когда та же проверка возможна без
снижения защиты.

## Что рекомендую

1. **Сейчас, без изменений безопасности:** тестировать всю цепочку через камеру **OBS Virtual Camera** —
   OBS → ИИ → Metal → OBS Virtual Camera → QuickTime / FaceTime / Zoom. Отличается только название камеры в списке.
   Передача кадров в камеру проверена: 60 fps, 296/297 кадров (живые тесты), 0 потерь из 105 157 за 30 минут.
2. **Своя «AI Virtual Camera» без снижения защиты:** нужен профиль Apple с правом System Extension — платный
   Apple Developer Program (99 $/год) **или** участие в чужой платной команде (владелец добавляет ваш Apple ID в
   команду на developer.apple.com → Users and Access; тогда `VCS_TEAM_ID` — ID этой команды).
3. **Если всё же выберете путь со снижением защиты** — скажите явно; я подготовлю скрипт установки под
   ad-hoc подпись и проверку, а шаги Recovery вы выполните сами (их нельзя и не следует делать автоматически).
