# Проверка на своём Mac через OBS Virtual Camera

Цепочка: **OBS → плагин vcstudio-obs → ИИ (Core ML) → ByteTrack → зоны → Metal → OBS Virtual Camera →
QuickTime / FaceTime / Zoom / браузер.** Своё системное расширение не нужно: камера OBS уже подписана и
установлена вместе с OBS. Почему своя «AI Virtual Camera» без платного аккаунта невозможна —
[CAMERA_LOCAL_SIGNING.md](CAMERA_LOCAL_SIGNING.md).

## Подготовка (один раз)

1. Установите приложение по [INSTALL_RU.md](INSTALL_RU.md) (DMG из GitHub Releases, OBS, плагин OBS).
2. В OBS: в сцене должен быть источник (камера, экран или видео). **Не нажимайте «Запустить виртуальную
   камеру»** в OBS, пока приложение отправляет в неё видео: обе программы писали бы в одну камеру.
3. В приложении: **Виртуальная камера → Отправлять обработанное видео в: OBS Virtual Camera**.

## 1. Самопроверка установки

```bash
"/Applications/AI Virtual Camera Studio.app/Contents/MacOS/AIVirtualCameraStudio" --self-check ~/Desktop/vcs-selfcheck.json
```

Прошло: последняя строка `OK: 11/12` или `12/12` (ffmpeg необязателен).

## 2. Замер всей цепочки (около 30 секунд) — кнопкой

Откройте OBS (с источником в сцене) и приложение. **Виртуальная камера → Проверить всю цепочку.**
Приложение само приостановит свою обработку, пропустит тестовую сцену 1080p60, затем ваше видео из OBS
через ИИ и Metal в камеру OBS Virtual Camera, примет его так же, как QuickTime или Zoom, и покажет результат
в окне. Отчёты сохраняются в папку приложения — кнопка **Открыть папку отчётов**
(`~/Library/Application Support/AIVirtualCameraStudio/reports/`). Никаких разрешений на «Рабочий стол»
и никакого Терминала не нужно. При первом запуске macOS спросит доступ к камере для приложения — разрешите.

| В результате | Прошло |
|---|---|
| «УСПЕХ» в обеих строках | да |
| кадр/с у клиента | ≈ 60 у тестовой сцены; = частоте OBS у вашего видео |
| обработка видна | 100 % (или близко) |
| ошибок отрисовки | 0 |
| отброшено очередью камеры | малая доля при 60 кадр/с, 0 при 30 кадр/с |

Пришлите текст результата (его можно выделить мышкой) или два файла из папки отчётов.

### Через Терминал (если нужно)

```bash
open -W -n "/Applications/AI Virtual Camera Studio.app" --args --pipeline-e2e-test "$HOME/Library/Application Support/AIVirtualCameraStudio/reports/e2e-synthetic.json" --seconds 20 --device "OBS Virtual Camera" --sink "OBS Camera Extension Stream Sink"
```

Если файл не появился:
- `open` написал ошибку о невозможности открыть приложение — DMG из интернета на карантине: один раз откройте
  приложение правой кнопкой → Открыть, или `xattr -dr com.apple.quarantine "/Applications/AI Virtual Camera Studio.app"`;
- `Unable to find application` — приложение не в «Программах»: укажите его настоящий путь;
- путь на «Рабочий стол»/«Документы» — macOS может молча не дать доступ; пишите отчёт в папку приложения, как выше.

## 3. Сторонние программы (вручную, 2 минуты)

Откройте приложение снова, включите, например, **Превью → Скрыть лицо** — так обработку видно сразу.

| Программа | Где выбрать камеру | Что должно быть |
|---|---|---|
| QuickTime Player | Файл → Новая видеозапись → стрелка рядом с кнопкой записи → **OBS Virtual Camera** | лицо пикселизировано |
| FaceTime | меню **Видео** → **OBS Virtual Camera** | то же |
| Zoom | Настройки → Видео → Камера → **OBS Virtual Camera** | то же |
| Chrome / Safari (Google Meet) | значок камеры в адресной строке или настройки встречи → **OBS Virtual Camera** | то же |

При первом выборе камеры macOS спросит разрешение на камеру для этой программы — разрешите.

## Формат пикселей

**Настройки → Формат пикселей: NV12** (по умолчанию с версии 0.3.2). Замер в камеру OBS, 20 с, 1080p60: NV12 —
60,1 кадр/с у клиента, **0** отброшенных из 1165, задержка 4,0 мс; BGRA — 60,1 кадр/с, 22 из 1163, 3,2 мс.

## Chrome

Chrome видит **OBS Virtual Camera**, но кадры получает, только если у самого Chrome есть системное разрешение на
камеру: «Системные настройки → Конфиденциальность и безопасность → Камера → Google Chrome». На этом Mac Chrome
его не имел (macOS показала запрос «Разрешить "Google Chrome" доступ к камере?») — после «Разрешить» откройте
страницу с камерой (например, Google Meet → проверка камеры) и выберите OBS Virtual Camera.

## 4. Восстановление

| Действие | Ожидаемое поведение |
|---|---|
| Закрыть OBS и открыть снова | приложение переподключается само (попытка каждые 5 с); проверено: подключилось через ~2 с после запуска OBS |
| Закрыть приложение и открыть снова | захват стартует сам, вывод в камеру OBS возобновляется; сторонняя программа на это время видит последний кадр или заставку OBS |
| Запустить вторую копию приложения | вторая сообщает о первой и закрывается (две копии мешали бы друг другу в камере) |
| **Аварийный прямой проход** (Превью) | камера получает исходное видео без обработки |

## Результаты на Mac mini M2 Pro (Mac14,12), macOS 27.2.1 (2026-11-12)

Команды — как в разделе 2, через dev-сборку (`build/AI Virtual Camera Studio Dev.app`). Кнопка «Проверить всю цепочку» на этом Mac: тестовая сцена 60,1 кадр/с у клиента, обработка в 99 % кадров, 29 из 675 отброшено очередью камеры; ваше видео из OBS 30,1 кадр/с, 100 %, 0 из 346; захват после проверки перезапустился сам.

| Замер | Синтетика 1080p60 | Видео из OBS (OBS 1080p30) |
|---|---|---|
| Кадров у независимого клиента | 1152 за 20 с, **60,0** разных/с | 583 за 20 с, **30,1** разных/с |
| Разрешение у клиента | 1920×1080 | 1920×1080 |
| Обработка видна | 100 % кадров | 100 % кадров |
| Вход → отправка в камеру | 2,8 мс (p95 5,3) | 3,0 мс (p95 4,3) |
| Отправка → клиент (отдельный тест камеры) | медиана 8,4 мс, p95 19,2 мс | — |
| Отброшено очередью камеры OBS | 28 из 1158 (2,4 %) | 0 из 593 |
| Ошибки отрисовки | 0 | 0 |
| ИИ | yolo11n-seg, 20 раз/с, 14,4 мс | yolo11n-seg, 20 раз/с, 10,0 мс |
| Металл (GPU) | да | да |

Отброшенные кадры при 60 fps — это очередь самой камеры OBS (она отбрасывает кадр, когда очередь полна, и
не блокирует отправителя); клиент всё равно получил 60 разных кадров в секунду. При 30 fps потерь нет.
30 минут непрерывной работы на этом Mac: 0 потерь из 105 157 кадров ([STABILITY.md](STABILITY.md)).

**Не проверено здесь:** QuickTime, FaceTime, Zoom, Meet — им нужно разрешение на камеру (выдаёт пользователь),
Zoom не установлен. Независимый клиент в замере использует тот же системный путь (AVFoundation), что и они.
На M5 ожидаются те же или лучшие цифры (ранние замеры на M5 — [BENCHMARK.md](BENCHMARK.md)).
